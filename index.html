THE PROJECT

From child-company raw data to parent-company analytics.

UDP models a realistic consolidation problem: a child FMCG business has its own customers, products, pricing and order data. The pipeline standardizes that data, creates analytics-ready Gold data, and prepares it for integration with a parent company's Gold analytics model.

The implementation uses the Bronze/Silver/Gold pattern, Delta tables, Spark transformations, Unity Catalog schemas and both full-load and incremental fact processing.

01

Data quality & standardization

The Silver layer handles real-world dirty data rather than assuming clean CSVs. Customer processing includes duplicate removal, whitespace trimming, city typo correction, title casing, missing-city handling and ID normalization.

DeduplicationNormalizationDQ
B
02

Product master alignment

Product processing fixes category casing and spelling, derives division and variant, creates a deterministic product_code using SHA-256 and keeps invalid product IDs from breaking downstream joins.

PySparkSHA-256Data Model
C
03

Messy pricing made analytical

Pricing data arrives with multiple date formats and invalid/negative price values. The Silver layer parses multiple formats, converts valid numeric values, fixes negative prices and maps non-numeric values to a controlled fallback.

try_to_dateValidationEnrichment

04

Full + incremental fact loads

Orders are processed at daily grain and then aggregated to monthly grain for the target analytics model. The project includes a full-load notebook and a separate incremental-load path with staging for newly arrived data.

Delta + Change Data Feed

The project writes Bronze/Silver datasets as Delta tables and enables Delta Change Data Feed on the relevant tables, supporting a stronger foundation for downstream change-aware processing.
